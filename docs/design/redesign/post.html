Diff-only saves: never lose a form edit again

How drafts, version checks and unsaved-change guards work together in a CMS editor.

PParker VuOct 12, 20266 min readformsux
On this page3
  • 01 Send only what changed
  • 02 Guard the exit
  • 03 Compare options

Most lost edits are not bugs in the save button. They are races: a second tab, a slow request, a token refresh in the middle of a long form.

01Send only what changed

The editor keeps the last saved snapshot. On save, it sends a patch with the changed fields and the version it started from.

const patch = diff(saved, draft)
await api.patch(`/admin/posts/${id}`, { ...patch, version })
NoteA 409 means someone else saved first. Show both versions; never overwrite silently.

02Guard the exit

Route changes and tab closes ask before discarding a dirty form. The guard reads the same diff, so it never nags about a clean form.

If the user typed it, the app owns it until it is saved.

03Compare options

StrategyPayloadConflict handling
Full replaceWhole documentLast write wins
Diff + versionChanged fields409, show both
Key takeaways
  1. Diff against the last saved snapshot, not the initial load.
  2. Send the version you started from; handle 409 visibly.
  3. One dirty-state source for save, guard and badge.
