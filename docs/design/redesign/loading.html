R4bLoading system

Every wait has a shape.

Skeletons are built from the same grid, aspect ratios and line boxes as the content they stand in for, so nothing moves when data lands. Shimmer is a compositor-only sweep and stops under reduced motion. Each board names the Next.js file or TanStack state that renders it.

05 · Parity

The no-shift rule, measured

Media boxes come from aspect ratios or from width and height. Text boxes are bounded by a two-line clamp plus min-height: 2lh, and the skeleton draws exactly two lines. The Playwright parity test compares these two boxes on every card type.

e2e/loading.spec.ts → expect(skeletonBox).toEqual(contentBox) ± 1px · CLS ≤ 0.02 on delayed API routes

06 · Pending

Navigation, refetch and submit

The route bar only appears if a navigation is still pending after 120ms. A refetch never replaces content with a skeleton. A submit locks the button width, keeps focus, and announces its state politely.

useLinkStatus() → <RouteProgress/> · isFetching && !isPending → <FetchBar/> · form.state.isSubmitting / mutation.isPending → <Button loading>
Topic
  Sending your message…
  • Contact form submitting. TanStack Form isSubmitting sets aria-busy on the form. Inputs dim and stop taking input, but keep their values. The submit button is locked.
  • Errors keep the draft. On failure the button returns to idle, the error shows inline under the form (role="alert"), and nothing typed is lost.
  • Success replaces the form with the existing “sent” card at the same height, so the footer does not jump.
  • Announcements. One polite live region per page reads “Sending…”, then “Sent” or the error. Spinners are aria-hidden.

The loader inserts w_32,e_blur:1000,q_1,f_auto after /upload/ for a ~300 byte preview. The server inlines it as blurDataURL, so the placeholder paints on first render without another request. Generated covers (no image) need no placeholder.

08 · First visit

The ink curtain: once per session, at most 700ms, never blocks input

Only the first hard load of a session gets it. A tiny inline script in <head> sets html.intro before first paint, but only if sessionStorage is empty, motion is allowed and Settings.ambientEffects is on. The real page renders under the curtain (SSR), so input is never blocked. The overlay holds no large text, so it cannot become the LCP element.

app/[locale]/(site)/layout.tsx → <IntroCurtain/> (server) + inline gate script · hero line-up delayed +400ms while html.intro
