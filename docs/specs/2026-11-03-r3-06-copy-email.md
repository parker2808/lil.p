# R3-06: reliable public email action

## Scope

- Use the site settings contact email in the public contact card, CTA, and command palette.
- Share one copy operation: secure Clipboard API first, then a temporary selection fallback; preserve focus and avoid copying an empty address.
- Show localized success/failure toasts through the public site shell. Keep a visible, distinctly named `mailto:` link beside copy actions.

## Acceptance

- EN/VI copy buttons and email links have distinct accessible names and at least 44px mobile targets.
- Rejected or unavailable Clipboard API writes try the fallback. A failed fallback shows a failure toast while the email link remains usable.
- No contact address is hardcoded or included in fixtures, captures, or logs.

## Tests and captures

- Unit: successful browser copy, denied or unavailable browser write, failed fallback, and missing email.
- Production-build Playwright: real EN/VI contact routes, keyboard focus, success/failure toasts, blocked clipboard, mailto and mobile geometry.
- Capture success/failure at 1440/390 in light/dark in the assigned public Desktop folder, with a tuple manifest.
- Run `pnpm check:all`, update Graphify, README, context §§7/9, and lessons.
