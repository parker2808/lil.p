# D5 V13 metadata/error localization and V05 editor evidence

## Contract

- Server-rendered `/admin`, `/admin/pages` and `/admin/pages/[key]` titles follow the `NEXT_LOCALE` cookie (EN/VI), including the title template. The page name uses the existing localized page-name catalog; unknown keys remain unmodified rather than interpolating unsanitized HTML.
- Client schema issues and server `fieldErrors` keep their original field paths and API codes. EN keeps original messages; VI maps known validation shapes and uses an honest localized generic invalid-value message for unknown server strings instead of exposing English copy. Existing input and draft values must remain untouched.
- A real D2 draft supplies the revision for 768px EN/VI light/dark editor screenshots. Attach both image captures and the server response JSON to the CI Playwright report, with no mocked API.

## Evidence and limits

- `admin-locale.spec.ts` checks server page titles after changing the cookie; `SchemaForm.test.tsx` and `map-field-errors.util.test.ts` check client/server VI errors and retained neighboring values. `cms-builder-live-journeys.spec.ts` uses the real API draft, reloads for each 768px capture, and verifies the exact same revision/tree.
- **V05 remains GAP on this D5 branch.** `BuilderDraftService.publish()` still rejects a valid tree with `CONFLICT: Tree publishing is not enabled`; editor→published public→preview for one tree revision requires the D6 integrated feature branch and its separate exact-head test. These editor captures cannot be substituted for that chain.
- **V13 full route/state matrix remains GAP.** This PR only addresses the two reviewed P2s; it is not a full WCAG or manually spoken screen-reader signoff.
