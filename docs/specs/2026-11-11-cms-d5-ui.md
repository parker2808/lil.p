## Frozen integration contract

The D4 shell accepts `{state: {document, selectedId}, onDispatch(command): CompositionResult, renderProperties?: ({state,onDispatch}) => ReactNode}`. Only the host owns document, selection, history and autosave. D4 commands are one atomic transaction each; `select` does not enter history. The D5 core `@parker2808/cms-core/tree` exports `applyTreeOperation`, `commitTreeHistory`, `createTreeHistory`, `undoTreeHistory`, `redoTreeHistory`, `endTreeTyping`, `DraftAutosave` and `starterComponentSchemas`. The host adapter first checks D4's typed/slot-validating result, translates `insert`, `move`, `remove` and `reorder` (a same-parent `move` with post-removal index) to exactly one core `TreeOperation`/`commitTreeHistory` call, checks the resulting tree matches the validated composition and returns its synchronous `CompositionResult`. It never applies D4's provisional tree to history before committing the core operation. `select` updates selection without history; validated whole-document `replace` uses one history snapshot because core has no replace operation. Typed rejections do not enter history. Property changes use D5's `property`/`clear-override` operations; base/tablet/mobile edits commit one history entry. Host-generated EN/VI field labels and feedback never fall back to English in VI.

Only eligible custom pages may activate a D2 tree draft: `GET /admin/pages/:key/builder/draft` returns `{mode:'legacy'|'tree', revision: decimal string, tree: TreeDocument|null}`; activation uses `POST .../builder/activate` and tree saves use `PUT .../builder/draft` with `{tree, expectedRevision}`. Never treat `home` or other core page keys as activated drafts. The standalone gated study remains available for unactivated pages, clearly labelled as local-only. After activation, the host must use D2's acknowledged revision. Tree publish remains disabled until D3 parity and server authorization.

The D5 `DraftAutosave` serializes debounced saves and preserves local edits after errors; on 409, timeout or ambiguous response it enters review, fetches a fresh remote and requires explicit user action. A matched read can acknowledge a timed-out save; a divergent remote stays in conflict until the user explicitly exports local JSON and chooses to reload. Never silently rebase or force-write. Retry rereads first. `offline` is a host presentation of connection failure, not an invented core status. On navigation/refresh with unacknowledged edits, retain a bounded page-scoped recovery copy without credentials and offer an explicit restore/export choice; never call that copy “saved.”

The implemented host has one `TreeHistory` ref and state projection; `onDispatch` owns selection/composition, `onEdit` commits typed property operations, and undo/redo replace the same history document. `home` never calls D2. Custom pages require an explicit activation before saving; a draft read failure leaves the editor local-only. Retry first rereads the remote through `DraftAutosave.review()` and only acknowledges a matching remote. A divergent remote cannot be overwritten by retry. The host stores a bounded local recovery copy per authenticated user and page until its active draft is acknowledged. The shell has one Properties mount: desktop inspector above 1100px, named modal sheet at or below 1100px.

Use host-owned shadcn `Button`, `Input`, `Textarea` and `Select` with core CSS variables (`Switch` for boolean schema fields); the starter component schemas have no checkbox/radio field. Keep touch targets ≥44px. Mobile Properties mounts only in the D4 named sheet. Do not edit D1/D2 core or APIs, B1 goldens, migrations, legacy page editor or public renderer. EN/VI and light/dark at 1440/768/390, keyboard/SR names, focus and axe are the visual gate. Browser/e2e/visual and disposable MySQL require `~/.t3/locks/lilp-e2e.lock`; formatting, units and Graphify do not. The PR remains draft and does not merge or deploy.
