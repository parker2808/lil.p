## API error localization boundary (P3 audit)

`apps/api/src/modules/pages/builder-draft.service.ts` returns English `message` fields for validation, not-found and revision conflicts. `apiClient` preserves those in `ApiError`, but the builder does **not** display the message: `BuilderHost` catches activation/read failures and selects EN/VI `noAccess`/recovery copy; its autosave controller in `packages/cms-core/src/tree/autosave.ts` branches on HTTP 400/409 and exposes only `invalid`/`conflict`/`review`, which the host maps to EN/VI status text. The D6 version action catch maps HTTP 400/409 and other failures to localized `versionInvalid`/`versionConflict`/`versionFailed` or `publishedReview`; history load displays localized retry instead of the server error. Validation field errors are not rendered verbatim in this UI. This is a builder-UI code audit, **not** a claim that API errors or other admin views are localized, or that failure states have passed browser CI. No D2 message contract changes are needed for this P3.
