## Properties and responsive behavior

Select a node by stable ID and derive fields from the **registered tree** component/layout schema, not B4 legacy `BlockDefinition`. Show localized label, help, error, inherited/overridden badge and source breakpoint. `responsive.base` is required; optional `mobile`, `tablet`, `desktop` are shallow overrides of base (`resolveResponsive`). Editing an inherited field at a breakpoint creates only that field's override; **Unset** removes that key, and removes the empty breakpoint object, without changing base or other breakpoints. Switching preview devices or selecting a node never writes. For grid, base/tablet/desktop columns require 2–4 and mobile may be 1–4. Validate any proposed edit with `readTree` and host policy **before** committing it to history; invalid/unknown values, unregistered types, unsafe URLs and budget violations keep the original document and show a localized, associated field/slot error. Never coerce away unknown/future fields or silently strip rejected input. Host-defined per-component props/labels and accessible custom widgets remain host-owned.

Duplicate/copy allocates fresh IDs across the full subtree, validates slots/count/depth/bytes before committing, and preserves source nodes verbatim. The preview uses D3's shared SSR path and the same resolved props; an editor-only preview must never invent published output. Undo/redo must restore the exact tree and selection without changing published versions. EN/VI labels and error messages, light/dark contrast, keyboard focus and named controls, ≥44px mobile targets and reduced motion are required at 1440/390 plus tablet device simulation.

## History, autosave and conflict state

Treat add/move/delete/duplicate and a committed property edit as **one atomic history operation each**. Coalesce consecutive typing on the same field until blur/explicit commit or a bounded idle window; never coalesce across node/breakpoint changes. New operation after Undo clears redo. Explicit Undo/Redo buttons and platform shortcuts have localized names/live announcements; never intercept text-input native undo while it owns focus. Keep unsaved local history across network errors and conflicts. A confirmed save updates the acknowledged baseline/revision but does **not** discard later local edits; specify a visible, tested history checkpoint before truncating old entries. A server save response for an older in-flight tree must never replace newer local state.

Use D2's proposed `GET /admin/pages/:key/builder/draft`, `POST .../builder/activate` and `PUT .../builder/draft` only after D2 freezes its DTOs and Parker approves DDL. Compare-and-swap uses the last **acknowledged decimal-string** `draftTreeRevision`, never `updatedAt` or a JS number. Debounce dirty drafts; serialize writes (one in flight), cancel stale timers on navigation, and queue the latest tree after a successful acknowledgement. On success set revision from the response, mark **saved only if** the acknowledged tree still equals the current local tree, then flush a queued change with the new revision. Invalid draft gets a typed 400 `VALIDATION_FAILED` without mutation; never drop local state. Offline/timeout/5xx leaves the attempted and newer edits dirty; Retry first reads the server revision or uses an idempotency guarantee proven by D2, rather than blind duplicate writes after an ambiguous response. A 409 `CONFLICT` must keep the unsent document/history and acknowledged baseline unchanged, stop automatic saves and disable Publish. **Review changes** displays local versus fresh server tree/revision; explicit reload, copy/export, or user-confirmed merge/rebase is needed before a new CAS. Never auto-merge, force-write, discard, or retry using the remote revision. Publish is enabled only for an acknowledged conflict-free draft that passes `validateTreeForPublish` **on the server**, after D3's release gate. The existing legacy publish/discard routes cannot bypass this revision contract.

Crash/refresh recovery must be demonstrated, not assumed: either a bounded local recovery copy (page/user scoped, no credentials, expired/cleared on explicit resolution) or a clearly signalled unsaved-changes prompt plus explicit export/recovery. Do not call unsaved edits “saved” merely because they are in memory or local storage. Include concurrent tabs, edit-during-request, save→Undo→Redo, page navigation, timeout-after-commit, offline recovery, 409 after remote publish/restore, empty/no-H1 draft autosave and the repaired empty-page publish rejection. Server tree failures map to D2's 400 `VALIDATION_FAILED`, corrupt stored snapshots to existing 400 `INVALID_BLOCKS`, conflicts to 409; do not introduce a new generic HTTP shape.

- Roll back the D5 UI/autosave flag and keep the last confirmed D2 draft and compatible reader. Preserve/export any dirty local draft before disabling UI; do not delete tree columns, change published snapshots, force a stale revision or silently fall back to legacy `PageBlock`.
