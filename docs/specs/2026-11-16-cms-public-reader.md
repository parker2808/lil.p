# CMS public reader (draft, flag OFF)

1. Keep preview/admin and all non-Page reads on the legacy API; `CMS_PAGE_READ_SOURCE=legacy|cms` defaults to legacy.
2. Server-only `CMS_PUBLIC_API_ORIGIN` serves `GET /api/public/pages/:key?locale=en|vi` without cookies or authorization.
3. Require an exact versioned envelope `{ contractVersion: 1, publishedVersion: positive integer, page: existing public Page DTO }`; reject wrong keys, invalid DTOs, missing versions and draft-shaped responses.
4. Bound CMS fetch to 2.5 seconds. Only timeout/network/5xx may use a last-good validated CMS response (same key/locale, ≤24 hours, in-process) or the existing published Page API **only when** `CMS_LEGACY_READ_FALLBACK_ENABLED=true` while that read source remains approved. Invalid DTO, 404 and misconfiguration fail closed; draft/preview never serve anonymous readers. No database/schema changes.
5. The CMS fetch uses short 30-second ISR data-cache TTL tagged `cms:page:<key>:<locale>`; successful responses are checked for contract version, page key/locale and monotonic published version. The in-process last-good map is keyed by page + locale and pins version; it is not a shared durable cache, so cold instances with no fallback fail safely. The URL fetch cache is page+locale (not version) and the version-pinned map is process-local: production proof must establish current-pointer discovery and cache propagation.
6. Separate `POST /api/cms/revalidate`: require Unix-seconds timestamp within five minutes, unique delivery ID (best-effort in-process deduplication for 10 minutes), HMAC-SHA256 of the exact request bytes with `CMS_REVALIDATE_SECRET`, valid page key and positive version. Fail closed without a secret or flag. Reserve each ID as `in_progress` with its payload digest; only mark it completed and advance the observed version after both locale tags and paths succeed. A partial failure returns 503 and permits retry of the same signed body; changed bytes for the same ID return 409. This process-local state is **not** cross-instance replay prevention; production rollout requires a durable shared atomic idempotency/version store (≥10 minutes) and rate limiting before enabling this flag.
7. Mock the CMS API and webhook in unit tests; preserve existing browser coverage. This PR neither enables the flag nor migrates data, changes admin routes or authorizes a cutover.

The endpoint/envelope/signature align with the consumer spec at cms-core PR #6 (`32fb13f`); that spec itself is a proposal. Do not enable production reads before durable replay/last-good design, CMS API implementation, contract reconciliation and independent review.

**Free durable-store proposal for review:** use the planned separate CMS database on its free tier for an atomic delivery ledger (`deliveryId`, digest, status, lease, version) and version-pinned validated published snapshots keyed by page and locale. Give the lil.p server-only adapter narrowly scoped access to this store, with a lease/CAS operation for webhook retries and a read path for cold-instance fallback. Verify the free-tier capacity, credential boundary, direct availability during CMS API outages, and pointer reconciliation before implementation. This proposal changes neither lil.p's production schema nor this draft's default-off behavior; the store is still unimplemented and blocks cutover.
