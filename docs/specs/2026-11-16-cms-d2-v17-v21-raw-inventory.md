## Combined-head evidence artifacts

CI's unit and API E2E jobs upload `cms-v17-v21-unit-<PR head>-<tested merge>` and `cms-v17-v21-api-<PR head>-<tested merge>`. Their JSON manifests include both checkout identities; compare them against the exact combined-head run, not only the stacked D2 PR run. The unit manifest records the source fixture's **literal UTF-8 byte length/hash**, canonical JSON hash, preserved nested property and eight named unsupported variants with their typed rejection and unchanged input hash. The API manifest records three disposable-MySQL version snapshots' **canonical serialized DB JSON** byte lengths/hashes after a byte-for-byte before/after comparison, plus normalized legacy version/VI preview and nested tree route response hashes, rejected unknown-tree preview and future-tree version/preview HTTP statuses. It includes no raw page bodies or production identifiers.

MySQL JSON may normalize input whitespace/key order, so this is a canonical serialized DB byte comparison, **not** proof that the original source-file bytes survive DB ingestion. Compare source-file bytes separately in the unit artifact. An independent reviewer must diff both JSON artifacts across the combined head and the final main head, verify corresponding CI tests passed, and compare final public/preview route and golden outputs before marking the code portion of V17/V21 complete.
