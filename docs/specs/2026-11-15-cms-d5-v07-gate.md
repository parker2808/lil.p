# D5 builder history gate — V07

The D5 builder exposes **Duplicate / Nhân bản** for a selected node in the canvas toolbar and selection strip. The command allocates fresh IDs for every descendant, then the core validates the full copy against slot/size bounds before recording one atomic history entry. Invalid IDs or exceeded limits leave history and the tree unchanged. The buttons are keyboard-accessible and labelled in EN/VI.

The adapter tests check nested fresh IDs, atomic undo/redo, rejected collisions, 4-column row and 500-node bounds, and a 50-entry undo/redo cap. `apps/web/e2e/cms-builder-history.spec.ts` exercises authenticated real-API insertion, edit, duplicate and move undo/redo; verifies copied text and source properties survive an acknowledged save/reload; and checks offline failed-save undo/redo, explicit retry, and draft preservation across a rejected publish. The spec remains registered in `apps/web/e2e/shards.ts`. The earlier duplicate/move subset has exact-head `ready-e2e` CI evidence at `4fecf6e8` (run `43705931696`); **the added cases are pending exact-head CI and must not be counted PASS before it completes**. Tree publication is still disabled by D2, so no tree version can be created via this API: V10 publish/history/restore UI and the real version-restore boundary remain separate GAPs owned by D6. No local browser or database without the shared lock.
