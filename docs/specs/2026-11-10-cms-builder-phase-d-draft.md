## D1 — tree contracts, conversion, fixtures

**DRAFT — U3 design approved; pending B7.** Define a **new** `{ schemaVersion, root }` tree contract, with one `page` root and ordered `section` children. Use the U3 proposal's exact slots: `page.sections → section`, `section.content → heading | paragraph | image | button | divider | spacer | row | grid`, `row.columns → column` (2–4), and `column.content` / `grid.cells → registered content components`. U3's palette labels the row-with-columns item **Columns**; `column` is a structural child, not a tenth palette tile. Each node has a stable opaque ID, discriminated type, schema-validated props, visibility, and optional `mobile`/`tablet`/`desktop` overrides. Publish separate tree-component/slot and host-policy interfaces for allowed page keys, H1/required roles, URL/media/rich-text safety, and limits (max depth, count, per-type, payload size); settle numeric caps against B7 fixture performance before implementation, with server and editor using the same bounds. B4's `BlockDefinition`/`createRegistry` are the **legacy** contract/index, not a drop-in tree registry or slot validator; reuse `defineBlock`/`isBlockAllowedOnPage` only for registered legacy blocks with the host's built-in keys.

- Pure, ordered schema-version migrators accept known older fixtures, preserve stable IDs and content, and reject future or missing versions without rewriting persistence; test idempotence and deterministic output. Duplicate/copy uses new IDs, unlike reorder/restore.
- A pure, **opt-in** legacy block-list converter wraps each old block in an ordered section with a registered legacy-component node. Preserve key, type, props, `schemaVersion`, `isVisible`, `sortOrder`, `layout` and `surface` verbatim, including unknown types as lossless warning-bearing placeholders. `PageBlock.id` can seed a stable node ID on draft conversion; B4's `pageSnapshotBlockSchema` contains **no** ID (only `type`, `key`, `schemaVersion`, `props`, `layout`, `surface`, `isVisible`, `sortOrder`), so version conversion must derive deterministic IDs from a unique snapshot key (using `sortOrder` only to restore order, never as an ID that changes on reorder). Define a lossless collision/warning path for malformed duplicate keys before adoption; do not invent a stored block ID. Keep both conversion paths and round-trip fixtures distinct. Never persist or remove `PageBlock` rows just to preview. Host Home/Hero and fixed-page constraints remain on the legacy path.
- Acceptance: fixtures cover empty root, nested slots, duplicates, unknown/future types, bad URLs/rich text, excessive depth/size/count, and legacy round-trip equivalence; EN/VI, light/dark, 1440/390, WCAG AA, keyboard, no-data-loss and unchanged golden-contract obligations in the shared invariants are explicitly carried forward. No DB change in D1.
