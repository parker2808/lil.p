# CMS U0 — route/control inventory and pre-change baseline

Baseline: `main` `d0d474b` (2026-11-10). This is **source/test evidence**, not a live browser or full visual sign-off. No behavior, routes, components, API contracts, or DB schema were changed. See [U0 spec](../specs/2026-11-10-cms-u0-audit.md) and the CMS ADR in [PR #172](https://github.com/parker2808/lil.p/pull/172), which is not yet on `main`. A2/#174 and A3/#173 are separate draft PRs, absent from this baseline; A3's localized-field labels are U1 acceptance.

## Route source of truth

There are 43 `page.tsx` files: 12 under `apps/web/app/[locale]`, 31 under `apps/web/app/admin`. Route groups `(site)` and `(cms)` add no URL segment. The table covers all 43, with explicit page paths; `[key]`, `[id]`, `[slug]`, and `[...rest]` are dynamic and need valid fixtures for live checks. `next.config.ts` redirects seven About subroutes and `/admin/tags`; two legacy About experience page files redirect directly. `proxy.ts` applies locale middleware to public paths, login redirect only when the API origin is absent and access cookie is missing, CSP/nonce to admin/draft, and a coarse unknown-admin-section 404; authenticated admin layout independently calls `/api/auth/me` and redirects on 401. Do **not** equate nav visibility with direct-route API authorization.

The seven About-tab redirects are `/admin/{experience,education,skills,principles,process,stats,domains}`; their component files still exist but are not the rendered destination. Shared public shell is `SiteShell`; admin shell is `AdminShell` after auth in `(cms)/layout.tsx`. Both have controls beyond each page's own JSX. `ADMIN_NAV` in `apps/web/src/modules/admin-core/constants/admin-nav.constant.ts` lists `admin`/`user` for most entries, but `users`, `inbox`, `audit` only for `admin`; `audit/page.tsx` has an additional explicit role gate. Confirm deep-link restrictions and API guards during U1; do not infer from nav alone. Public preview uses `draftMode`, with snapshot and slug precedence guarded by existing tests. Loading/error/not-found boundaries live in `apps/web/app/[locale]` and `apps/web/app/admin/(cms)`; include each affected state in U1/U2 visual captures rather than mistaking page-file count for state coverage. EN/VI shortcuts/help strings exist in `apps/web/i18n/locales/{en,vi}.json`; **there is no `/help` page file**, so `/help` parity here means current shortcut/help copy where affected.
